## 实现范围

- `windows && pickerprocess` 构建使用同一 EXE 的专用子进程入口，在 `wails.Run` 前分流。依赖的 Go 初始化仍会运行，包括 winc 的 GDI+、公共控件及默认字体初始化；没有把它描述成零 GDI 初始化的纯 Win32 二进制。
- 匿名管道传递单次、严格校验的 JSON，最大 64 KiB；绑定版本、随机 nonce、父 PID、创建 FILETIME 及所属窗口。不通过命令行传递媒体路径。
- 父进程在写入请求前将子进程加入 kill-on-close Job；失败即拒绝，不退回进程内选择器。只有有效回复、实际正常退出和进程资源收尾完成后才能发布路径。
- 子进程在锁定的 STA 上创建真实 `IFileOpenDialog`，释放结果字符串、接口并退出 COM 后写回复。父进程继续承担媒体读取与会话所有权。
- 取消、崩溃、协议错误、十分钟超时和主窗口关闭分别有明确收尾。现有请求编号、丢失响应恢复及 JS 绑定保持兼容。保存对话框和非 Windows 平台不在此原型范围。

## 独立诊断复现

`native-002/MuxRay.exe` 通过 Go overlay 仅在父入口捕获 stdout、stderr、标准日志和 Go 崩溃输出；没有改变选择器逻辑。构建输入与首轮一致，overlay 和二进制单独绑定。额外日志句柄使它不适合直接与首轮资源计数作等价比较。

这轮仅用于打开后直接取消、捕获实际错误及调用栈；不套用六轮验收、30 秒文件行驻留和固定静置窗。`run-native-002/diagnostic-audit-addendum-002.json` 明确记录了该范围及事后登记时间。本报告尚未取得该诊断轮手动取消完成的证据，不将其计为已完成复现。

源码审读发现一个待验证路径：主窗口 `WM_SETFOCUS` → Wails `onFocus` → WebView2 `MoveFocus` → 错误回调 → `os.Exit(1)`。这是候选解释，尚未作为已确认根因或据此合入修复。
