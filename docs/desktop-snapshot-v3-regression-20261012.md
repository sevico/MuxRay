# H.264 检索快照 v3、Linux CI 与长文件生命周期验收

日期：2026-10-12。平台：Linux amd64，GTK 3.24.41、WebKitGTK 2.52.6
（webkit2gtk-4.1），Go 1.27.0、Node 22.22.2、Wails 2.14.0。

功能及工具提交：`bf49bca3f929059f36de1961f50d0f37c251051e`。
合同与边界见 [ADR-028](decisions/028-search-snapshot-v3-and-native-regression.md)。

## 功能与兼容性

桌面诊断快照显式请求 v3，保留 v2 的当前媒体曲线页，并增加当前已完成的
H.264 检索页。请求只提交 `requestId/start/filter`；服务端核对同文档保留结果，
不会接受客户端提供的结果行。导出包含实际扫描区间、索引总数、读取量、筛选、
结束状态及最多 64 行源证据。空结果页有效，未知证据不会变成否定结论。

捕获不重新读取或分析文件，也不遍历历史批次；总大小上限仍为 2 MiB。
详情和 Hex 跳转保留当前已完成批次，新检索会替换它。进行中、取消、失败或
过期请求不能提供已完成页，相应节导出显式 null 和省略原因；源变化和文档关闭
继续受既有有效性检查约束。
冻结后的保存内容不随后续选择或关闭变化，保存结果恢复语义保持不变。
未指定版本与显式 v1 仍返回 v1 形状，v2 合同及 CLI 合同保持兼容。

新增独立的 `linux-search-history` CI job：构建生产程序、检查生成绑定、生成独立
样本并执行默认完整九轮，核对运行前后产物哈希，失败时也上传 JSON、日志和哈希。
CI 使用 Ubuntu 24.04、Go 1.27.0、Node 24；本机 Node 22.22.2。远端 GitHub Actions
尚未运行，本记录中的通过结论来自本机检查和原生执行。

## 原生结果

全部 12 轮通过。每轮使用独立 D-Bus/Xvfb、应用配置目录和仅内存 GSettings，
通过实际 GTK/WebKitGTK/Wails 窗口执行打开、搜索、来源跳转、保存和关闭。
普通九轮顺序执行，长文件及受控轮另行运行。

| 普通生产场景 | 结果 | 秒 | 核验要点 |
| --- | --- | ---: | --- |
| MP3 合并 Tag | PASS | 166.49 | 帧 26；338 byte 回指；两个前序槽位与当前槽位 |
| MP3 拆分 Tag | PASS | 121.44 | 正确来源 Tag/帧；依赖窗口与合并样本一致 |
| MP3 音视频交错 | PASS | 151.35 | 视频不打断物理音频来源；窗口一致 |
| MP3 音频编码中断 | PASS | 99.52 | 不跨越 AAC 边界；unknown，缺少 10 byte |
| MP3 历史不足 | PASS | 93.55 | unknown，缺少 10 byte；仅保留当前槽位 |
| H.264 分页差异检索 | PASS | 152.28 | 四页 96 行；逐页 v3 导出、回看和源跳转 |
| H.264 未知证据 | PASS | 62.24 | 一页一行；unknown 及源范围保持正确 |
| H.264 部分 IDR 证据 | PASS | 77.50 | 一页 30 行；部分覆盖保留已观察到的正向 IDR |
| H.264 缺少配置 | PASS | 67.65 | 一页 30 行未知；不猜测 NAL 长度 |

普通九轮共 30 份实际 v3 快照重新做 schema、源文件哈希和源位校验；累计七页
157 条 H.264 结果均逐行对照原始字节 oracle。另核对 11 次 MP3 来源 Hex 点击、
五次来源 Tag/帧跳转，以及四次 H.264 来源 Hex 点击和 Tag 详情跳转。
MP3 导出没有检索页时保留 null 与省略原因，H.264 页导出不强制要求选中 Tag 或 Hex。
证据位于 `.cache/sv3-final-nine/`，独立复核见该目录的 `independent-audit.json`。

所有 12 轮均保持源文件不变，关闭后源 FD 释放，应用正常退出，无强制结束应用
或遗留进程。测试辅助进程的清理信号单独保留在各轮记录中，不算应用正常退出证据。
39 份实际快照均经独立重读校验；未用最终 PASS 替代原始快照、界面和来源核验。
验收后只读检查全局 `toolkit-accessibility` 和 `screen-reader-enabled`，均保持 false。

### 长文件：普通生产程序

固定生产程序通过一轮长文件验收，用时 340.69 秒。样本为 12,080,133 byte、
17,160 Tag（15,600 个 AVC 媒体 Tag），DTS 范围 0–831,560 ms。
检索完整覆盖 68 批、2,080 条声明差异结果；逐批游标、每行关系和源范围均对照
原始字节 oracle。连续回退 64 批到历史上限，确认不可继续回退，再前进回末尾。
最终 `[17152,17160)` 是零命中页，仍成功导出 v3，保留实际覆盖和 exhausted 状态。

长文件仅导出最终检索页，普通 H.264 四轮逐页导出。证据位于
`.cache/sv3-final-long/`；长文件结果不能代表多小时业务录制或持续解码性能。

### 取消与关闭：独立受控程序

两轮均从同一干净提交和前端资源构建独立 Go overlay 程序，未修改普通生产程序。
在第一次实际搜索 `ReaderAt` 调用的包装层等待显式释放，记录真实请求
offset 223、length 2；底层源读取在释放后执行。受控程序仅把 AVC 搜索任务截止
延长至 90 秒，门控 60 秒安全释放。普通生产程序仍为 3 秒任务截止且不含门控。

| 场景 | 结果 | 秒 | 阻塞秒数 | 核验行为 |
| --- | --- | ---: | ---: | --- |
| 搜索取消 | PASS | 101.23 | 3.10 | 实际取消命令；导出 null 检索页；点击重试恢复 v3 页 |
| 搜索期间关闭 | PASS | 86.59 | 2.30 | 等待读取期间禁止打开；释放后关闭源 FD；重新打开并检索 |

`0f8cb435d7f03df0f13d346de9b2a617b1d6d08166d5636e57b5dde5b72e2327`；
关闭程序 SHA-256 为
`d8a8712c331aea0ea78c2ac091c111213ac252d16f774274f53e5ee7d3a527db`。

收据绑定运行 ID、PID 和进程令牌，验证进入、`context canceled`、释放的时间顺序；
deadline exceeded 或安全超时不能算取消通过。实际点击前和释放前源 FD 均仍持有，
读取释放后恢复正常操作并退出。原始 UI、全部七份实际快照、每行源证据、构建输入
和进程代际经过独立复核。两轮源未变化、无强制结束应用、无残留进程；关闭轮工具

各轮 `independent-audit.json` 和 `controlled-build-archives.json` 保存复核及归档哈希。

## 保留的适配失败与验收边界

初次纯检索页导出已成功，但旧核验器假定每份快照都含 Hex，导致聚合失败。
现在使用纯检索页核验入口，已有要求 Hex 的详情核验保持不变。原目录
`.cache/sv3-trial-unknown` 保留。取消和关闭初次工具等待的局部文字未通过
WebKitGTK 可访问性接口暴露；改为核对实际可访问状态栏、按钮状态、读取收据
和导出内容，保留 `.cache/sv3-gate-cancel-trial`、`sv3-gate-close-trial`。

长文件初次采集整个界面树每页耗时约 10–15 秒，主动终止并记录清理，目录
`.cache/sv3-long-trial` 保留。后续采集准确定位的 H.264 检索区域，仍逐行核对
DTS、关系、IDR 和源范围；校准目录 `.cache/sv3-long-calibration` 不计入最终轮数。

H.264 检索仅分析 NAL 头；声明差异不是损坏诊断，IDR 观察不证明完整图像或
独立解码。MP3 来源表示物理主数据槽位，不重建 reservoir 或解码音频。
长样本为重复片段及声明变异组成的结构测试，不是业务录制或连续可解码证明。
受控读取实验模拟无法立即返回的读取，不声称重现内核 I/O 卡死。
Windows/macOS 原生行为及既有 Windows 辅助选择器问题均未由本轮 Linux 验收确认。

本机 `.cache` 证据不提交 Git。复现命令与依赖见
[回归工具说明](../tools/codec-regression/README.md#long-search-and-controlled-native-cancellation)。
