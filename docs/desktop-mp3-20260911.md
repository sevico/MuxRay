# MP3 桌面详情与 Windows 验证（2026-09-11）

基线为 `9a6c161`。本批接入 MP3 桌面详情，沿用 ADR-006 的首帧头范围与 ADR-013
的文档所有权、详情任务和预算；不修改 accepted ADR、CLI 合同、schemas 或 goldens。

当前状态：实现、自动检查和 Windows 原生验收均已完成。实现提交为 `4dbdbaa`；
原生验收使用该提交对应的生产程序与受控程序，期间未修改产品代码。

## 实现

- `detailview` 音频入口复用现有 AAC/MP3 分发，增加 `mp3Audio` 投影。前端增加相应
  kind、标题和边界说明，继续使用原字段表与请求恢复控制器；Wails 方法和 DTO 外壳不变。
- 展示 FLV 音频声明、MPEG-1/2/2.5 Layer III 首个固定帧头、原始位字段、可推导的
  采样率/声道/码率/帧长，以及 SoundData 和未解析正文范围。
- 原始字段保留 byte/bit Span，派生字段不伪造位置。FLV 声道/采样率声明与 MPEG
  参数分开；free-format 不输出未知的码率和帧长。CRC 仅是头部声明，不代表校验通过。
- 首帧头语法完成不证明整帧存在、可解码或后续帧/VBR/CRC 正确。`SoundFormat=14`
  和空 Audio 的现有 unsupported 行为保留；短 MP3 正文显示准确诊断，不生成伪帧头。
- 读取只触及所选 payload 的前五个字节；正常头因判别与位读取重复，累计最多九字节、
  六次 `ReadAt`。音频正文不加载，现有 512 字段、64 诊断、256 KiB JSON 上限不变。
- 桌面音频 Reader 保留首次短读或非 EOF 读取错误，阻止后续成功掩盖前次失败；
  满读 `io.EOF` 保持兼容。源错误是请求失败，不伪装为编码语法诊断；CLI 行为不变。
- 同文档单 worker、取消后的完整索引前缀、源变化粘滞检查、切换和阻塞关闭均复用
  既有机制，新增 MP3 路径的确定性测试。
