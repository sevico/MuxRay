# 桌面预览使用指南

MuxRay 用于只读检查本地 FLV 文件，把观察项定位到 Tag、字段与原始字节。
当前是本地开发预览；平台、已知问题和结果边界见[预览范围](preview-scope.md)。

## 开始一次分析

1. 在已安装 WebView2 Runtime 的 Windows x64 电脑上解压预览包，运行 `MuxRay.exe`。
   包内构建记录标识这份程序对应的源码、EXE 摘要和验收范围。
2. 点击“打开文件”，选择 FLV 文件，等待扫描结束。扫描期间可以取消；取消后的
   已保留 Tag 可以查看，但属于部分索引。一次只分析一个文件。
3. 查看扫描状态、Tag 数量和结构诊断。先确定下面哪一类任务能回答你的问题，
   按需加载对应结果；分析期间保持源文件不变。

扫描卡下的快捷导航可前往时间戳检索、趋势、Tag 索引、当前详情和 Hex。
**快捷链接只移动页面位置，不会自动启动检索或加载数据。** 详情和 Hex 随当前选择
出现；已有时间戳检索页时，可从趋势、详情和 Hex 返回查看。Hex 的“返回页首导出”
可直接回到保存入口。

Tag ID 和 Tag 内 MP3 帧号从 0 开始；DTS 的单位为毫秒，源位置通常显示字节偏移及
bit 偏移。不要把源文件顺序、原始 DTS 和播放时间当成同一种坐标。

## 任务一：不知道位置，查找时间戳回退、重复或大间隔

1. 前往“时间戳观察检索”，选择观察项；大间隔阈值默认为 1000 ms，按实际问题调整。
   点击“从头检索时间戳”。
2. 阅读本批检查范围和“连续已检范围”。每批最多检查 4096 个 Tag、显示 64 条观察。
   本批没有命中时，如尚未到索引末尾，点击“继续下一批时间戳”。继续沿用该批的
   筛选与阈值；修改条件后需从头检索。需要停止时点击“取消时间戳检索”。
3. 对命中行核对当前 DTS、差值、前驱 Tag/DTS、类型和 Stream ID。点击
   “Tag … · 趋势与详情”，等待所在的 256 Tag 趋势窗及详情加载。
4. 前往已加载趋势，查看相邻 Tag；在详情中点击有源位置的字段，或使用趋势中的
   “查看 Tag Hex”“查看 Payload Hex”读取字节。需要保留当前证据时再导出 JSON。

回退表示同类型、同 Stream ID 的当前原始 DTS 小于已知前驱；重复为相等；大间隔
严格大于设置值。它们都是容器时间观察，不直接证明播放异常或媒体损坏。前驱未知
时没有可比较差值；普通趋势的独立回查预算也可能让检索中已知的前驱显示为未知。

只保留当前检索批次，下一批会替换上一批。时间戳检索页本身不导出，因此应另记
筛选、阈值、累计检查范围和关注行，再导出定位后的趋势、详情与 Hex。
可对照[三批定位尾部回退的验收示例](desktop-time-search-20261018.md)。

## 任务二：已知时间、Tag 或结构问题，核对字段和字节

1. 前往 Tag 索引。有 Tag ID 时输入编号并点击“跳转 Tag”；只有大致时间时，使用
   Tag 类型及 DTS 起止筛选，再点击“应用筛选”。DTS 区间包含两端，结果按文件顺序。
   怀疑封装截断时，可选“Payload 截断”或相应 PreviousTagSize 结构状态。
2. 按页查看结果。空结果页可能只是本批未命中；“继续查找”或“下一结果页”才会
   检查后续范围。也可切到“诊断”，查看诊断代码及预期/实际值并定位源位置。
3. 选择 Tag 读取详情。AMF0 可查看脚本字段，AAC 可查看配置或 raw 包范围，AVC
   可查看配置、NAL 和有支持语法的字段，MP3 可查看帧及 side-info。
   对长文件 AVC，如提示参数准备未完成，使用界面提供的继续准备入口。
4. 点击字段或诊断的源位置，在 Hex 核对高亮字节与位范围。大字段只高亮当前
   Hex 窗口的交集；不支持的编解码器也可直接读取 Tag/Payload Hex。
5. 记录 Tag ID、字段名/诊断代码和源范围，导出当前证据后再切换到其他位置。

“部分解析”表示只保留了已确认字段，应一起查看详情诊断和未检查范围；没有某字段
不等于源文件没有该信息。跳转精确 Tag ID 会退出 Tag 筛选，趋势窗口可继续保留。
如需先观察整段媒体的码率或声明 GOP，可按需运行媒体概览、查看曲线并从点位进入
对应 Tag；曲线仍有自己的覆盖窗口，不代表解码帧或播放质量。

## 任务三：定位 MP3 变化或 H.264 SEI 证据

1. 找到“MP3 / SEI 批量检索”，选择“MP3 变化与停止”或“H.264 SEI 消息”，
   再按需要选择参数、码率、停止原因或 SEI 消息范围。选择类型/范围会开始相应
   检索，也可点击检索按钮从头开始。
2. 阅读本批范围、记录状态和覆盖缺口；尚未结束时点击“继续检索编解码器”。
   页面只保留当前批，需留存本批时先导出。
3. MP3 完整帧记录可点帧号进入相应详情；用“上一/下一 MP3 帧”或输入 Tag 内帧号
   继续查看。远处帧可能需要“继续定位 MP3 帧页”。停止记录只定位 Tag，不会
   伪造一个可查看的完整帧。需要分析回指时，点击“定位 MP3 依赖来源”，再查看
   来源 Tag/帧与 Hex。
4. SEI 记录可查看 NAL/消息序号、状态及时序上下文；通过“证据”“SPS”或
   “选择依据”的源位置按钮核对字节。缺少或含糊的 SPS 上下文保持未知。
5. 保持相关检索页及详情/Hex 已加载，点击页首“导出诊断 JSON”。当前已完成的
   MP3/SEI 检索页会随 v4 快照保存，包括覆盖范围；不会自动收集其他历史批次。

正常 VBR 的码率变化不等于损坏。MP3 依赖来源说明物理槽位范围，不重建 reservoir，
也不证明能解码。SEI 时序字段是源语法和声明，不是已重建的播放时间线。

## 保存与结束

点击“导出诊断 JSON”，在原生保存框选择新文件。快照冻结点击时已加载的有界结果，
不补做分析；检查所需 Tag、详情和 Hex 已完成后再保存。v3/v4 的范围和省略说明见
[预览范围](preview-scope.md#快照能证明什么)。报告可能包含 AMF 文本和原始媒体字节，
分享前应查看内容。

保存完成后点击“关闭文件”，确认回到空状态，再打开下一文件或正常关闭窗口。
如果界面显示正在确认打开、取消或保存结果，使用提供的确认/重试入口等待原请求
结果；不要用反复打开或重复保存来猜测它是否已完成。

## 遇到问题时记录什么

保留第一次失败的信息，先区分“源内容的诊断”与“应用操作失败”。记录：

- 包内构建提交和 EXE SHA-256、Windows/WebView2 版本，以及发生时间。
- 输入文件大小、SHA-256、扫描完整性、Tag 总数；能分享时优先提供最小可复现样本。
- 从打开文件开始的最短步骤、最后一次操作、预期和实际结果。
- 相关 Tag ID、MP3 帧号或 NAL/消息号、检索筛选与阈值、检查范围、错误代码及截图。
- 已成功保存的诊断 JSON；若未能保存，直接注明，不把没有报告当成没有问题。

发现源文件变化时关闭后重新打开；预算或未知提示先按覆盖范围解释。若程序异常退出、
保存失败或关闭文件失败，保留本次记录并停止该轮；不要为凑出成功结果反复重启，
也无需自行开展长时间资源采样。提交反馈前检查附件是否含不适合分享的媒体内容。
